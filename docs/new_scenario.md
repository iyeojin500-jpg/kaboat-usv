# AMR 3대 · 주문 1,000건 자동화 창고 — 실험설계 (최종)

> 사용자가 전달한 실험설계 원문 요약 (코드 구현 기준 문서).
> Before = CASE1(A*만, 문제 발생), After = CASE2(OR-Tools 배정 + Cooperative A* + 예약테이블). 사람 CASE 없음.

## 목적
입고~출고까지 최단거리 + 최소시간을 방해하는 문제를 수치화하고, Before(CASE1) / After(CASE2) 기대효과를
동일 조건·동일 주문으로 비교한다.

## 1. 창고 조건 (Before/After 동일, 알고리즘만 변경)
| 항목 | 설정 | 의미 |

| 창고 크기 | 가로 20m × 세로 30m | 중소형 창고를 격자로 표현 |
| AMR 수 | 3대 (AMR1·2·3 동시 운용) | 다중 AMR 배차·충돌·병목 관찰 |
| AMR 시작 위치 | 3대 서로 다른 위치 | 주문까지 초기 거리 차이 |
| 입고장 | 1곳 | 모든 주문의 시작점 |
| RFID 구역 | 1곳 (공용) | 여러 AMR 접근 시 병목 관찰 |
| 중앙 교차로 | 1곳 이상 | 동선 합류 → 경로/정면 충돌 발생 지점 |
| 저장구역 | A~J 10개 | 주문별 목적지 다름 |
| 좁은 통로 | 1개 이상, 한 번에 1대만 통과 | 대기·병목 측정용 제한구역 |
| 출고장 | 1곳 | 모든 주문의 종료점 |
| 이동 방식 | 대각선 금지, 상하좌우 격자 이동 | 최단거리 계산 명확화 |
| 랙 내부 통과 | 금지 (장애물) | 현실적 경로 |
| AMR 속도 | 3대 동일 | 알고리즘 외 변수 통제 |
| 공용구역 | RFID·중앙교차로·좁은통로·출고진입부 | 충돌·병목 측정 핵심 위치 |

## 2. 주문 1,000건 발생 조건
- 총 1,000건 (O0001~O1000), 전부 출고 완료 후 종료
- 발생 방식: 랜덤 (간격 고정 안 함). 피크시간엔 간격 짧게, 일반시간엔 길게
- 저장구역: A~J 중 랜덤, 랜덤 시드 고정(42) → Before/After 에 완전히 동일한 1,000건 적용
- 문제를 강제로 만들지 않음 — 조건이 맞을 때만 충돌·병목·비효율을 기록
- (선택) 여러 seed 로 반복실험

## 3. 입고→출고 시나리오 흐름 (주문 1건 기준)
| 단계 | 내용 | 발생 가능 문제 | 측정값 |
|---|---|---|---|
| 1 주문 발생 | 대기 큐에 추가 | 주문 적체 | 주문 발생시간 |
| 2 AMR 배차 | 3대 중 수행 AMR 선택 | 배차 비효율 | 실제 배차비용, 최소가능비용, 추가거리/시간 |
| 3 입고장 이동 | 배정 AMR 이 입고장으로 | 동선 겹침 | 이동거리, 이동시간 |
| 4 RFID 통과 | 공용 RFID 진입 | 병목·대기 | RFID 대기횟수·대기시간 |
| 5 중앙 교차로 | 동선 합류 | 경로·정면 충돌 | 충돌횟수, 충돌대기시간 |
| 6 A~J 저장/피킹 | 목적지에서 처리 | 비효율 배차로 불필요 이동 | 실제거리, 처리시간 |
| 7 출고 복귀 | 중앙교차로로 재이동 | 충돌 재발 | 충돌횟수, 지연시간 |
| 8 좁은 통로 | 1대씩 출고방향 진입 | 병목 | 병목횟수, 총·평균·최대 대기시간 |
| 9 출고 완료 | 작업 종료 | 앞 지연 누적 | 완료시간, 총 처리시간 |
| 10 통합 판정 | 문제·사람개입 검사 | 인력 의존 | 사람개입 횟수·시간 |

## 4. 문제점 + 사람개입 판정 기준
- **경로 충돌**: 2대 이상 AMR 이 같은 시간에 같은 좌표로 진입하려는 경우. 같은 AMR 들이 같은 위치에서
  연속 충돌 상태면 해소될 때까지 1회. 측정: 횟수, 충돌 대기시간, 평균/최대 지속시간
- **정면 충돌**: 두 AMR 이 같은 시간에 서로의 현재 위치로 이동. 해소될 때까지 1회. 측정: 횟수, 회피 대기시간, 평균/최대
- **병목**: RFID·중앙교차로·좁은통로·출고구역에서 다른 AMR 때문에 즉시 진입 못 하고 대기. 대기 시작~진입까지 1회.
  측정: 횟수, 총/평균/최대 대기시간, 구역별
- **배차 비효율**: 배정 AMR 의 예상 수행비용 > 그 시점 선택 가능 AMR 중 최소 가능 비용. 주문당 최대 1회.
  측정: 횟수, 추가 이동거리, 추가 예상시간, 비효율률
- **[사람개입] 장시간 정체**: 충돌·병목으로 연속 5초 이상 이동 못 함. 최초 5초 넘긴 순간 1회.
  측정: 횟수, 개입시간, 관련 주문수
- **[사람개입] 수동 배차 확인**: 단순 배차로 선택된 AMR 의 예상 비용이 최소 가능 비용보다 20% 이상 큼. 주문당 최대 1회.
  측정: 횟수, 개입시간, 관련 주문수, 주문 100건당 개입횟수
- 5초·20% 는 가정값 (실제 운영기준 확보 시 교체)

## 5. 기대효과 KPI
| 기대효과 | 계산식 | 연결 문제 | 목표 |
|---|---|---|---|
| 작업 처리시간 단축 | 총처리시간=출고완료−주문발생, 개선율=(B−A)/B×100 | 충돌·병목·배차비효율 | 20~30% ↓ |
| 설비 가동률 향상 | (이동시간+작업시간)/전체시간×100 | 충돌·병목 대기 | 15% ↑ |
| 재고 정확도 | 일치재고/전체재고×100 (RFID/WMS 데이터 별도 기록) | — | 98% ↑ |
| 인력 의존도 감소 | (B개입−A개입)/B개입×100 | 장시간정체·수동배차 개입 | 10~15% ↓ |
| 주문 대응시간 개선 | 작업시작−주문발생, 개선율=(B−A)/B×100 | 배차비효율·혼잡 | 25% ↑ |

## 구현 지시
1. 기존 시뮬레이션 코드 재활용. 사람 전용 CASE 없음
2. CASE1 = A*만 (단순 순차 배정, 독립 경로, 충돌 시 대기). 문제 발생해도 1000건 완주
3. CASE2 = A* 거리행렬 → OR-Tools 배정 + Cooperative A* + 예약테이블
4. 4장 판정 기준대로 측정 ('연속 상태는 1회' 규칙 준수)
5. 5장 KPI 5종 Before/After 개선율 표 출력
6. 재고 정확도는 RFID/WMS 데이터를 별도 기록해 계산
7. seed 고정(42), Before/After 동일 주문, 결과 숫자는 실제 실행값만
8. 측정값은 주문별/AMR별/시스템 3개 CSV 로 저장
